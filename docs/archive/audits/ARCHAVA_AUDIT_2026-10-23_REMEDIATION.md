Notes on reproducibility:

- **The workspace suite passed once, in one process, and was also corroborated by batching.**
  The single-process pass came from stage 1 of `pnpm rust:verify-release`:
  `✓ cargo test --workspace (3139.9s)` with every module suite `ok`. The suite is I/O
  bound — each integration test provisions a disposable PostgreSQL cluster and applies
  ~23 ledgers — and standalone `cargo test` invocations launched inside this working
  session were terminated with SIGTERM at 5.5, 7.0 and 9.6 minutes with no OOM event and
  no failing assertion in the log, so the same targets were additionally run as four
  batched invocations: `archava-host` integration suites (96 tests: session, own,
  authority, crm, assistant), ERP accommodation/assets/attendance/billing/foodservice
  (59), ERP organizations/projects/proposals/purchasing/scheduling/subscriptions (68), and
  `--workspace --exclude archava-host` followed by `archava-host --lib` (52). Every
  invocation was green; no target was skipped and no target ran under different flags.
  `RUST_TEST_THREADS=8` is the working balance here; the earlier `4` was a memory guard
  that is no longer needed.
- **The security matrix was graded from per-step runs for the same reason.** Each
  `*:verify` / `*:verify-host` step (unit, CRM, Act, runtime, reuse, assembly, kits and
  every module) was run and logged individually in this session, then
  `node tools/security/verify.mjs` graded the proofs without `--run` and wrote
  `dist/security-proof/results.json`: 86/86 controls `passed`, `checkedAt`
  `2026-10-26T18:58:40.816Z`. That graded file is the evidence quoted above. The
  `--run` form (`pnpm security:verify`) executes the identical steps in one process and is
  what `.github/workflows/ci.yml` runs. Driving the steps individually produces the same
  proof files and the same grading; `--run` only adds the orchestration.
- One earlier run failed in `Doc-tests archava-adapters` with `can't find crate for
archava_domain`. The cause was a truncated `libarchava_domain-*.rlib` left by a killed
  build, not the tree: rebuilding the crate made the doctest compile and the next heavy
  run green. Recorded here so the same stale artifact is not mistaken for a regression.
- `pnpm verify` now runs the Rust fast gate only; the eight-gate wrapper is
  `pnpm legacy:verify`. Both are named in `docs/BUILD_STATUS.md` so a future reader does
  not read "verify passed" as the full set.
- The security matrix itself is long enough to brush the same 45-minute cap when the host
  is otherwise busy: one attempt aborted at the `kits` step while a Rust build was running
  concurrently, and the same command passed on an idle machine. Run it alone, not beside a
  build.
