# Persistent authenticated CRM — local M3 evidence

Checkpoint `4f24164` preserves the PRD/audit, cleanup and M1/M2 implementation.
This change adds a persistent host with owner/staff/viewer credentials, trusted
sessions, operator enrollment/recovery and actual backup restoration. Setup and
run instructions are in [CRM runtime](CRM_RUNTIME.md).

The host consumes installed compiled CRM/identity packages with the same dashboard.
Identity owns credentials/sessions and grants no business permission by itself.
Membership/resource checks remain in CRM. Neither the assistant core nor CRM gains
a mandatory identity-provider dependency. No external dependency was added;
the adapter reuses pinned pg/Zod and Node crypto.

Database verification uses real PostgreSQL 18.6; Node 22.22.3 and pnpm 10.15.1
are the tested environment. Later host/frontend adjustments also passed focused
typecheck/lint/format and runtime/browser checks. The build prevents TypeScript
workspace aliases from replacing installed modules, retains public class identity
and performs a fresh generated install so an old local-file lock cannot preserve
stale code. Browser inputs exclude the server adapter and identity implementation.

The session implementation stores keyed hashes, not cookie tokens. Idle/absolute
expiry, credential rotation, durable login budgets and operator membership revocation
are verified. Browser mutation requests require both Origin and session-bound CSRF.
Unknown accounts receive the same generic credential result and fixed KDF work.
Fake ambient PostgreSQL destinations/service settings are injected in verification;
the host and backup tools use only their private owned cluster.

The restore test backs up existing contacts, activity, memberships, command receipts
and audit, then changes the original dataset/password. It restores into a new
database, verifies the original remains usable and checks the backup's data/audit
and canonical retry receipt. Restored sessions and credentials cannot regain access
without explicit account recovery. The command fingerprint key survives through
the private metadata pair; the identity key rotates. This is initial-schema
recovery evidence, not a later-version migration or uptime/RPO/RTO guarantee.

[Saved proof](audit/2026-10-08-crm-runtime-proof.json) includes compiled artifact

Deliberate HTTP 401/403 checks produce expected browser console entries; no

The host is configured for local private operation. Public deployment/TLS/proxy,
MFA/SSO/enrollment policy, automated backups/alerts, privacy retention/export,
later upgrades, shared realtime presence and durable Act/provider work remain
separate release gates. Machine CRM writes and the three Pending Act tasks are
unchanged. Historical commercial-readiness percentages are not recalculated.
CI now includes the runtime verifier; remote CI/deployment has not been run.
No existing user database, provider, company website or pricebook was changed.
